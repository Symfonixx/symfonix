Einführung & Vision

Symfonix Business Suite wurde für Organisationen entwickelt, die über ein Flickwerk voneinander getrennter Software hinausgewachsen sind — bei dem der Vertrieb in einem Werkzeug, die Lohnabrechnung in einem anderen und die Bestandsverwaltung in einem dritten liegen, jeweils mit eigener Anmeldung, eigenem Datenmodell und fehleranfälliger Synchronisierung.

Der Name Symfonix spiegelt die Produktphilosophie wider: eine bewusst orchestrierte Symphonie von Geschäftstechnologien. Anstatt Unternehmen zu Systemintegratoren zu machen, stellt Symfonix Business Suite eine Core Engine bereit, die unabhängige, entkoppelte Geschäftsmodule je nach betrieblichem Bedarf dynamisch lädt — heute CRM, Finanzen vom ersten Tag an und weitere Funktionen, wenn die Organisation wächst.

Symfonix Business Suite basiert auf einem modernen Laravel-Fundament mit modularer Architektur (nwidart/laravel-modules) und richtet sich an Agenturen, Dienstleistungsunternehmen, Distributoren und mittelständische B2B-Unternehmen, die ein einheitliches betriebliches Rückgrat benötigen, ohne auf die Flexibilität zu verzichten, nur die tatsächlich benötigten Module zu aktivieren.

Warum Symfonix Business Suite?

Die meisten B2B-Organisationen häufen im Laufe ihres Wachstums Softwareschulden an. Hier ein CRM, dort eine Buchhaltungslösung, eine Tabelle für Bestände und E-Mail für alles Weitere. Jede Ergänzung führt zu:

  • Datensilos — Kundendaten im CRM stimmen nicht mit den Rechnungsempfängern im Finanzsystem überein.
  • Integrationsaufwand — Zapier-Workflows, CSV-Exporte und manuelle Abstimmungen binden Zeit in Entwicklung und Betrieb.
  • Unübersichtlichen Berechtigungen — die Zugriffskontrolle ist über zahlreiche Administrationsoberflächen verschiedener Anbieter verteilt.
  • Fehlender Berichtstransparenz — die Geschäftsleitung erhält keinen funktionsübergreifenden Echtzeitüberblick.

Symfonix Business Suite beseitigt diese Reibungsverluste von Grund auf. Wird ein Abschluss im CRM gewonnen, kann das Projektmodul die Leistungserbringung anlegen. Wird ein Produktverkauf erfasst, verbucht Finance den Umsatz. Nimmt HR neue Mitarbeitende auf, werden Berechtigungen über das einheitliche Rollensystem von Spatie weitergegeben. Eine Anmeldung. Eine verlässliche Datenbasis.

Warum Unternehmen Symfonix Business Suite wählen

  • Niedrigere Softwarekosten Ersetzen Sie sich überschneidende Abonnements und reduzieren Sie den Wartungsaufwand externer Integrationen.
  • Schnellere tägliche Abläufe Verbinden Sie Vertrieb, Finanzen, Projekte, Personalwesen und Content-Teams durch gemeinsame Workflows statt manueller Übergaben.
  • Verlässliche Geschäftsdaten Verwalten Sie Kunden, Transaktionen, Projekte und Berechtigungen in einem kontrollierten System für bessere Berichte und Entscheidungen.
  • Kontrolle und Datenhoheit Betreiben Sie die Plattform selbst, steuern Sie Zugriffe nach Rollen und behalten Sie die Kontrolle über Unternehmens- und Kundendaten.
  • Wachstum ohne Systemwechsel Beginnen Sie mit den heute benötigten Modulen und aktivieren Sie weitere Funktionen, wenn Teams, Niederlassungen und Prozesse wachsen.

Architektonischer Mehrwert für B2B-Unternehmen

Für Unternehmenskunden und technische Entscheidungsträger schafft Symfonix Business Suite in drei Bereichen Mehrwert:

  • Gesamtbetriebskosten Konsolidieren Sie Lieferantenverträge, reduzieren Sie den Integrationsaufwand und betreiben Sie die Lösung auf eigener Infrastruktur oder in verwaltetem Hosting — bei vollständiger Datenhoheit.
  • Operative Geschwindigkeit Modulübergreifende Workflows werden innerhalb von Millisekunden auf einem gemeinsamen Schema ausgeführt. Keine Webhook-Verzögerungen, keine Synchronisierungswarteschlangen und keine Dashboards mit „Daten noch nicht verfügbar“.
  • Zukunftssichere Modularität Neue Geschäftsfunktionen werden als installierbare Module ausgeliefert, ohne den Kern neu zu schreiben. Die Plattform wächst mit dem Unternehmen statt gegen seine Anforderungen.

Für flexible Kombination entwickelt. Symfonix Business Suite ist kein monolithisches ERP, das vollständig übernommen werden muss. Aktivieren Sie die heute benötigten Module und ergänzen Sie weitere, sobald sich die Anforderungen entwickeln — die Core Engine übernimmt Erkennung, Routing und Berechtigungsregistrierung automatisch.

Systemarchitektur

Symfonix Business Suite folgt einer modularen Schichtenarchitektur, in der die Geschäftslogik in eigenständigen Modulen liegt, von einer gemeinsamen Core Engine orchestriert wird und auf einer einzigen relationalen Datenbank aufsetzt.

Jedes Modul ist ein vollwertiges Laravel-Paket unter Modules/ mit eigenen Routen, Controllern, Modellen, Migrationen, Ansichten und Service-Providern. Die Core Engine erkennt aktivierte Module beim Start, registriert deren Service-Provider, führt Routendateien zusammen und verarbeitet Migrationen in der Reihenfolge ihrer Abhängigkeiten.

Die Core Engine

Die Module Core und Base bilden die System-Engine. Core stellt den Installationsbefehl (php artisan app:install), gemeinsame Hilfsfunktionen und die Bootstrap-Logik bereit. Base verwaltet globale Einstellungen, Länder, Niederlassungen, SEO, Backups, den Dateimanager, /humans.txt sowie APIs & Integrationen (SMTP und WhatsApp Cloud API). Unter Systemkonfigurationen liegen außerdem Fixer-Zugangsdaten und die ZKTeco-Fingerabdruckgeräte.

Zu den zentralen Aufgaben der Core Engine gehören:

  1. Modul-Lebenszyklus — Module über standardisierte Artisan-Befehle registrieren, aktivieren, deaktivieren und migrieren.
  2. Berechtigungszusammenführung — Berechtigungsdefinitionen aller aktiven Module in einer einheitlichen Spatie-Permission-Registrierung bündeln.
  3. Administrationsoberfläche — das Metronic-basierte Administrationslayout, die Navigationsstruktur und die Inertia-Pipeline zum Rendern von Seiten bereitstellen.
  4. Modulübergreifende Ereignisse — das Ereignissystem von Laravel ermöglicht lose Kopplung, etwa wenn Finance auf Ereignisse zu versendeten Rechnungen aus CRM-Abonnements reagiert.

Datenkonsistenz

Da alle Module eine gemeinsame Datenbank nutzen, wird die referenzielle Integrität auf Schemaebene durchgesetzt und nicht lediglich durch nächtliche Synchronisierungsaufträge angenähert. Fremdschlüssel verbinden Kunden mit Abschlüssen, Mitarbeitende mit Gehaltsdaten, Produkte mit Bestandsbewegungen und Projekte mit Unternehmen.

Spatie Laravel Data DTOs standardisieren den Datentransfer zwischen den Schichten und gewährleisten typsichere Nutzdaten über Modulgrenzen hinweg. Übersetzbare Modelle (über spatie/laravel-translatable) halten CMS-Inhalte und Produktkataloge sprachübergreifend konsistent, ohne Datensätze zu duplizieren.

Leistung

Symfonix Business Suite ist auch unter realer Unternehmenslast auf reaktionsschnelle Administration ausgelegt:

  • Inertia.js ermöglicht SPA-ähnliche Navigation ohne die Komplexität einer separaten Frontend-API-Schicht.
  • Eager Loading & Repository-Muster verhindern in stark frequentierten Modulen wie CRM und Finance N+1-Abfrageprobleme.
  • Redis beschleunigt optional Sitzungsspeicherung, Cache und Warteschlangenverarbeitung für Hintergrundaufgaben wie die PDF-Erstellung von Rechnungen und den Versand von Benachrichtigungen.
  • Laravel Pulse bietet bei Aktivierung eine Leistungsüberwachung im Produktivbetrieb.
  • Die Asset-Pipeline über Vite erzeugt optimierte Frontend-Bundles mit Cache-Busting.

CRM & Pipelines

Das CRM-Modul ist der Umsatzmotor der Symfonix Business Suite. Es verwaltet den gesamten Lebenszyklus vom Erstkontakt bis zum gewonnenen Abschluss — mit visuellen Pipeline-Phasen, Aktivitätsverfolgung und Abonnementverwaltung für wiederkehrende Umsatzmodelle.

Zentrale Oberflächen

  • Lead-Management — eingehende Leads mit benutzerdefinierten Feldern, Tags und Quellenzuordnung erfassen, qualifizieren und konvertieren.
  • Vertriebspipeline — Pipeline im Kanban-Stil mit konfigurierbaren Phasen (Standard: Lead → Qualifiziert → Angebot → Verhandlung → Gewonnen/Verloren). Phasenwechsel per Drag-and-drop mit Aktivitätsprotokollierung. Zugewiesene sehen nur eigene Abschlüsse, sofern sie nicht sales.deals.view_all haben.
  • Angebote / Quotes — Positionen mit Steuer und Rabatt, PDF-Download, Erstellen aus einem Abschluss und öffentlicher Link zum Annehmen oder Ablehnen.
  • Unternehmensdaten — B2B-Kundenverwaltung mit verknüpften Kontakten, Abschlüssen, Projekten, Angeboten und Abonnementhistorie.
  • Aktivitäten & Aufgaben — Anrufe, Besprechungen und Nachfassaktionen planen und Leads, Abschlüssen oder Unternehmen zuordnen.
  • Abonnements — wiederkehrende Dienstleistungsverträge mit Verlängerungsverfolgung und Finance-Integration für die Rechnungsstellung verwalten.
  • E-Mail-Marketing — eingereihte Kampagnen an Abonnenten, Kontakte, Anfragen oder benutzerdefinierte Adressen mit automatischer Deduplizierung.
  • WhatsApp-Marketing — Meta-Cloud-API-Vorlagenkampagnen an Leads, Kontakte, Abschlüsse, Anfragen oder eigene Nummern. Versand über die Queue, Zustellung je Empfänger protokolliert.
  • Verkaufsprognosen — wahrscheinlichkeitgewichtete Pipeline-Projektionen nach Phase, Vertriebsmitarbeitenden und erwartetem Abschlussdatum.
  • CRM-Dashboard — filterbare KPIs, Trichter, Bestenliste und Aktivitätsfeed. Widgets lassen sich ein- und ausblenden sowie umordnen.
  • Vertriebsziele — Team- und Einzelquoten festlegen und anhand der Pipeline-Leistung überwachen.

Pipeline-Workflow

Abschlüsse durchlaufen die unter CRM/database/seeders definierten Pipeline-Phasen. Phasenwechsel lösen Ereignisse aus, auf die andere Module reagieren können — beispielsweise kann das Verschieben eines Abschlusses auf „Gewonnen“ automatisch einen Project-Datensatz anlegen und eine Finance-Transaktion erzeugen.

💡

CRM-Zugriff ist granular. Typische Schlüssel: crm.leads.*, sales.deals.view_all, sales.quotes.*, marketing.whatsapp.send, sales.forecasts.view. Legacy-Namen wie CRM Management werden bei der Installation umgeschrieben.

Personal Zugriffskontrolle

Personalwesen

Das User-Modul dient als Personal- und Identitätsfundament der Symfonix Business Suite. Es verbindet Personaldaten mit Systemauthentifizierung, Rollenzuweisung und der über das Finance-Modul integrierten Lohnabrechnung.

Zentrale Oberflächen

  • Mitarbeiterprofile — umfassende, mit Benutzerkonten verknüpfte Personaldaten einschließlich Kontaktdaten, Abteilungszuordnung und Beschäftigungsstatus.
  • Rollenbasierte Zugriffskontrolle — Spatie Laravel Permission mit Katalog group.tab.action. Die Installation legt Admin sowie Szenario-Rollen an: HR Manager, Sales Manager, Finance Manager, Project Manager, Operations Manager.
  • Berechtigungsmatrix — Aktionen je Ressource (view, create, edit, delete sowie send, export, approve, view_all, manage, reply, restore) unter Benutzerverwaltung → Rollen.
  • Fingerabdruck-Anwesenheit — optionale ZKTeco-TCP/IP-Anbindung. Mitarbeiter-IDs entsprechen Geräte-User-IDs. Konfiguration unter Systemkonfigurationen → Fingerprint.
  • Urlaub & Recruiting — Urlaubsanträge, Stellen und Bewerbungen.
  • Portal-Dashboard — Self-Service für Mitarbeitende sowie ein Kundenportal für Angebote.
  • Integration des Team-Moduls — öffentliche Teamprofile, die auch in /humans.txt erscheinen.

Brücke zwischen HR und Finance

Personaldaten sind direkt mit der Gehalts- und Provisionsverwaltung in Finance verbunden. Bei der Lohnabrechnung werden Transaktionen mit vollständigem Prüfverlauf den richtigen Mitarbeitenden zugeordnet — ohne CSV-Importe zwischen Personal- und Buchhaltungssystemen.

Buchhaltung Umsätze & Ausgaben

Finanzen

Das Finance-Modul deckt durchgängig mehrwährungsfähige Finanzprozesse ab — von der täglichen Transaktionserfassung über Gehaltsauszahlungen und Provisionsberechnungen bis zur Rechnungsstellung und Ausgabenkategorisierung. Es reagiert auf Ereignisse aus den Modulen CRM und Product, damit die Bücher ohne manuelle Dateneingabe korrekt bleiben.

Zentrale Oberflächen

  • Transaktionen — Echtzeitbuch mit Einnahmen und Ausgaben, Kategorisierung, Filtern und einem Livewire-Dashboard-Widget für die heutigen Transaktionen.
  • Buchungssätze — Unterstützung der doppelten Buchführung für Organisationen mit formalen Buchhaltungsanforderungen.
  • Rechnungen — aus Abschlüssen erzeugen, PDF, Status gesendet/bezahlt/storniert, Steuerpositionen und Kundenbenachrichtigungen.
  • Debitoren — offene und überfällige Rechnungen für Dashboard und Berichte.
  • Gehälter — Verwaltung wiederkehrender Lohn- und Gehaltszahlungen, verknüpft mit Personaldaten im User-Modul.
  • Provisionen — Verfolgung von Vertriebsprovisionen, verknüpft mit CRM-Abschlüssen und Vertriebszielen.
  • Ausgaben — Erfassung betrieblicher Ausgaben mit anpassbaren Kategorien und Vorsteuer.
  • Produktverkäufe — Umsatzerfassung aus Verkäufen des Product-Katalogs.
  • Rechnungsbenachrichtigungen — automatische Kundenbenachrichtigungen beim Versand von Rechnungen über Laravel-Event-Listener.
  • Währungskontext — getrennte Basiswährung der Buchhaltung, Transaktionswährung und sitzungsbezogene Anzeigewährung mit Wechselkurssnapshots zum Buchungszeitpunkt.

Ereignisgesteuerte Integration

Finance nutzt das Event-/Listener-Muster von Laravel für modulübergreifende Workflows. Beispielsweise reagiert NotifyCustomerOfInvoiceSent auf Rechnungsereignisse und versendet Benachrichtigungen. So bleibt Finance von den Implementierungsdetails des CRM entkoppelt, während der Datenfluss erhalten bleibt.

Mehrwährungssystem einrichten

Symfonix unterscheidet drei Währungskonzepte: Die Standardwährung ist die Basiswährung der Buchhaltung, jeder Geschäftsvorgang behält seine Transaktionswährung, und die Auswahl in der Kopfzeile der Administration steuert ausschließlich die Anzeigewährung des Benutzers. Buchungssätze speichern sowohl den zum Buchungszeitpunkt geltenden Kurs von der Ausgangs- in die Basiswährung als auch den umgerechneten Basisbetrag. Eine Änderung der Anzeigewährung verändert niemals die gespeicherte Buchung.

EinstellungZweckStandardwert
FINANCE_DEFAULT_CURRENCYBasiswährung der BuchhaltungUSD
FINANCE_SUPPORTED_CURRENCIESDurch Kommas getrennte, für Benutzer verfügbare WährungenUSD,EUR,GBP,TRY
FIXER_API_KEYZugangsdaten für Fixer oder API LayerLeer
FIXER_BASE_URLAPI-Endpunkt für Wechselkursehttps://data.fixer.io/api

Benutzer mit der Berechtigung Settings Management können die Standardwährung und den Fixer-Schlüssel unter Systemkonfigurationen → Finanzen überschreiben; gespeicherte Einstellungen haben Vorrang vor Umgebungswerten. Die Liste unterstützter Währungen bleibt umgebungs- bzw. konfigurationsgesteuert. Kostenlose Fixer-Tarife liefern EUR-basierte Kurse, daher leitet Symfonix andere Basiswährungen über EUR-Kreuzkurse ab.

Terminal 
# Eine Kursaktualisierung einreihen (erfordert einen laufenden Queue-Worker)
php artisan finance:fetch-exchange-rates

# Sofort abrufen und optional die Basis überschreiben
php artisan finance:fetch-exchange-rates --sync
php artisan finance:fetch-exchange-rates --base=EUR --sync
⚠️

Verwenden Sie Ersatzkurse nicht für die produktive Buchhaltung. Bei der Installation werden ungefähre Basiskurse eingespielt; ein fehlender Fixer-Schlüssel oder nicht verfügbarer gespeicherter Kurs kann zum Ersatzwert 1.0 führen. Konfigurieren und überwachen Sie die Synchronisierung, bevor Sie echte Transaktionen buchen. Eine Änderung der Standardwährung nach vorhandenen Buchungen erfordert eine kontrollierte Migration, da historische Basisbeträge ihre ursprüngliche Buchhaltungsbasis behalten.

Compliance Ledger & Meldung

Steuern

Das Tax-Modul speichert inklusive oder exklusive Sätze (optional je Region), wendet sie auf Rechnungs- und Produktverkaufspositionen an und bucht erhobene Umsatzsteuer sowie gezahlte Vorsteuer in ein eigenes Ledger. Meldungsberichte fassen die Nettosteuer für einen Zeitraum zusammen und können exportiert werden.

  • Steuersätze — Prozentsatz, inklusive/exklusiv, optionaler ISO-Regionscode, Standardsatz für Rechnungen und Abonnements.
  • Steuer-Ledger — chronologische Ein- und Ausgangseinträge zu Rechnungen, Positionen und Ausgaben.
  • Meldungsbericht — Periodensumme erhobener versus gezahlter Steuer.
Analytik CSV- / PDF-Export

Berichte

Das Reporting-Hub liefert abteilungsübergreifende Analysen mit gemeinsamen Zeitraumfiltern und CSV-/PDF-Export. Jede Abteilung hat eigene Berechtigungen (reporting.finance.view, reporting.sales.export usw.).

  • Finanzen — Umsatz, Ausgaben, Gewinn, Debitorenalterung, Steuerübersicht.
  • Vertrieb — Pipeline-Trichter, Gewinn-/Verlusttrend, Mitarbeiterleistung.
  • Marketing — E-Mail- und WhatsApp-Kampagnenvolumen, Zustellrate, Lead-Quellen.
  • Betrieb — Tickets, Projekte, Fingerabdruck-Anwesenheit.
  • Mitarbeitende — Auslastung, zugewiesene Projekte, Gehaltstrend, Einzelprofil.
Inhalte Mehrsprachig

Content-Management (CMS)

Das CMS-Modul betreibt die öffentliche Website neben der Administrationsoberfläche. Es bietet eine vollständige Umgebung zur Inhaltserstellung mit Mehrsprachigkeit, SEO-Integration und Rich-Text-Bearbeitung über TinyMCE.

Zentrale Oberflächen

  • Seiten — statische Seiten wie Über uns, Leistungen und Kontakt mit Slug-basiertem Routing und übersetzbaren Inhaltsfeldern erstellen und verwalten.
  • Blog — Beiträge mit Kategorien, geschätzter Lesezeit, Titelbildern und SEO-Metadaten veröffentlichen.
  • Häufig gestellte Fragen — strukturierte Verwaltung häufig gestellter Fragen für Support- und Marketingseiten.
  • Unsere Kunden — Logo-Einträge für die öffentliche Website.
  • SEO-Einstellungen — globale und seitenspezifische SEO-Konfiguration über die SEO-Oberfläche des Base-Moduls, einschließlich Meta-Titeln, Beschreibungen und Open-Graph-Tags.
  • Leistungspräsentation — das Services-Modul erweitert die CMS-Funktionen um Leistungskategorien und Angebotsseiten für Agenturen und Beratungsunternehmen.

Lokalisierung

Inhalte können über mcamara/laravel-localization und Spatie Translatable in Englisch, Arabisch, Türkisch und Deutsch übersetzt werden. Das Theme der öffentlichen Website unterstützt für arabische Sprachversionen von Haus aus ein Rechts-nach-links-Layout.

Installation

Führen Sie die folgenden Schritte aus, um eine neue Instanz der Symfonix Business Suite bereitzustellen:

  1. Repository klonen und Umgebung konfigurieren

    Kopieren Sie die Umgebungsdatei und tragen Sie Ihre Datenbankzugangsdaten ein:

    Terminal 
    cp .env.example .env

    Bearbeiten Sie .env und konfigurieren Sie Ihre Datenbankverbindung:

    .env 
    DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=symfonix
DB_USERNAME=root
DB_PASSWORD=

FINANCE_DEFAULT_CURRENCY=USD
FINANCE_SUPPORTED_CURRENCIES=USD,EUR,GBP,TRY
FIXER_API_KEY=
FIXER_BASE_URL=https://data.fixer.io/api

DOCS_ENABLED=true

  2. Abhängigkeiten installieren

    Installieren Sie die PHP- und Node.js-Abhängigkeiten und kompilieren Sie anschließend die Frontend-Assets:

    Terminal 
    composer install
npm install && npm run build

  3. Installationsbefehl ausführen

    Der Artisan-Befehl app:install übernimmt den vollständigen Bootstrap-Prozess — Migrationen, Ausgangsdaten, Berechtigungen, CRM-Pipeline-Phasen, grundlegende Währungseinstellungen und Wechselkurse sowie die Erstellung des Administratorkontos:

    Terminal 
    php artisan app:install

    Eigene Administratorzugangsdaten:

    Terminal 
    php artisan app:install \
  --email=you@company.com \
  --password=secret \
  --name="Your Name" \
  --mobile=1234567890

  4. Anwendung starten

    Terminal 
    php artisan serve

    Rufen Sie /admin auf und melden Sie sich mit den nach der Installation angezeigten Zugangsdaten an.

💡

Der Installationsbefehl erzeugt APP_KEY, führt alle Modulmigrationen aus, legt Länder und grundlegende Wechselkurse an, erstellt Anwendungsberechtigungen, richtet die standardmäßigen CRM-Pipeline-Phasen ein und weist der Rolle Admin sämtliche Berechtigungen zu.

Module aktivieren & deaktivieren

Die Modulaktivierung wird über module.json und die Modulstatusdatei gesteuert:

Terminal 
# Alle Module und ihren Status auflisten
php artisan module:list

# Ein Modul aktivieren
php artisan module:enable Stock

# Ein Modul deaktivieren
php artisan module:disable Testimonial

# Migrationen für ein bestimmtes Modul ausführen
php artisan module:migrate CRM

Neues Modul erstellen

So erzeugen Sie das Grundgerüst eines neuen Geschäftsmoduls, beispielsweise eines eigenen Berichtsmoduls:

Terminal 
php artisan module:make Reporting

# Modulkomponenten erzeugen
php artisan module:make-controller ReportController Reporting
php artisan module:make-model Report Reporting -m
php artisan module:make-migration create_reports_table Reporting

Registrieren Sie Berechtigungen im Service-Provider Ihres Moduls und ergänzen Sie sie im Berechtigungs-Seeder des Installationsbefehls, damit sie bei Neuinstallationen automatisch bereitgestellt werden.

Frontend-Entwicklung

Starten Sie während der Entwicklung den Vite-Entwicklungsserver zusammen mit der Laravel-Anwendung, um Hot Module Replacement zu nutzen:

Terminal 
# Terminal 1 — Laravel
php artisan serve

# Terminal 2 — Vite HMR
npm run dev

# Terminal 3 — Queue-Worker (für asynchrone Aufgaben)
php artisan queue:work

Produktivbereitstellung

Wenden Sie nach der Installation in Produktivumgebungen die folgenden Optimierungen an:

  1. Umgebung konfigurieren

    .env 
    APP_ENV=production
APP_DEBUG=false
CACHE_DRIVER=redis
QUEUE_CONNECTION=redis
SESSION_DRIVER=redis

  2. Produktionsabhängigkeiten installieren

    Terminal 
    composer install --no-dev --optimize-autoloader
npm ci && npm run build

  3. Migrationen und Cache ausführen

    Terminal 
    php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

  4. Hintergrunddienste konfigurieren

    Richten Sie über cron einen Queue-Worker und den Scheduler ein. Der Scheduler aktualisiert die Wechselkurse stündlich synchron. Eingereihte WhatsApp-Kampagnen, Marketing-E-Mails und manuelle Kursabrufe benötigen den Worker.

    crontab 
    * * * * * cd /path-to-symfonix && php artisan schedule:run >> /dev/null 2>&1
⚠️

Checkliste für den Produktivbetrieb: Stellen Sie sicher, dass APP_DEBUG=false gesetzt ist, beschränken Sie bei Bedarf den Zugriff auf /admin, aktivieren Sie die Zwei-Faktor-Authentifizierung, übertragen Sie .env niemals in die Versionsverwaltung, konfigurieren Sie einen gültigen Fixer-Schlüssel und überwachen Sie den letzten erfolgreichen Kursabruf unter Systemkonfigurationen → Finanzen. Gespeicherte Kurse werden nicht automatisch wegen ihres Alters abgelehnt. WhatsApp-Zugangsdaten unter APIs & Integrationen setzen. DOCS_ENABLED=false, wenn /docs nicht öffentlich sein soll.
