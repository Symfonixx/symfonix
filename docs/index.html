Introduction & Vision

Symfonix Business Suite was built for organizations that have outgrown the patchwork of disconnected software — where sales lives in one tool, payroll in another, and inventory in a third, each with its own login, data model, and sync failures.

The name Symfonix reflects the product philosophy: a symphony of business technologies, orchestrated with intention. Rather than forcing enterprises to become systems integrators, Symfonix Business Suite provides a core system engine that dynamically loads independent, decoupled business modules based on operational needs — CRM today, finance from day one, and additional capabilities as the organization evolves.

Built on a modern Laravel foundation with a modular architecture (nwidart/laravel-modules), Symfonix Business Suite targets agencies, service companies, distributors, and mid-market B2B enterprises that need a unified operational backbone without sacrificing the flexibility to enable only the modules they require.

🔗

Unified Ecosystem

Replace fragmented third-party SaaS subscriptions with one platform sharing a single database foundation and consistent user experience.

🧩

Modular by Design

Activate CRM, HR, Finance, Tax, Reporting, CMS, and other business modules independently. Each module is decoupled yet deeply integrated at the data layer.

⚡

🌐

Global Ready

Built-in localization (English, Arabic, Turkish, and German), role-based access control, and multi-branch organizational structures.

Why Symfonix Business Suite?

Most B2B organizations accumulate software debt over years of growth. A CRM here, an accounting package there, a spreadsheet for inventory, and email for everything else. Each addition creates:

  • Data silos — customer records in CRM don't match invoice recipients in Finance.
  • Integration tax — Zapier workflows, CSV exports, and manual reconciliation consume engineering and operations time.
  • Permission sprawl — access control fragmented across a dozen vendor admin panels.
  • Reporting blindness — leadership cannot get a real-time, cross-functional view of the business.

Symfonix Business Suite eliminates this friction by design. When a deal closes in CRM, the project module can spin up delivery work. When a product sale is recorded, Finance captures the revenue. When HR onboards an employee, permissions propagate through Spatie's unified role system. One login. One truth.

Why companies choose Symfonix Business Suite

  • Lower software costs Replace overlapping subscriptions and reduce the maintenance burden of third-party integrations.
  • Faster daily operations Give sales, finance, projects, HR, and content teams connected workflows instead of repetitive manual handoffs.
  • Reliable business data Keep customers, transactions, projects, and permissions in one governed system for clearer reporting and decisions.
  • Control and data ownership Self-host the platform, define access by role, and retain control over company and customer information.
  • Growth without replacement Start with the modules needed today and activate more capabilities as teams, branches, and processes expand.

Architectural Value Proposition for B2B Enterprises

For enterprise buyers and technical decision-makers, Symfonix Business Suite delivers value across three dimensions:

  • Total Cost of Ownership Consolidate vendor contracts, reduce integration maintenance, and deploy on your own infrastructure or managed hosting — full data sovereignty.
  • Operational Velocity Cross-module workflows execute in milliseconds against a shared schema. No webhook delays, no sync queues, no "data not yet available" dashboards.
  • Future-Proof Modularity New business capabilities ship as installable modules without rewriting the core. The platform grows with the enterprise, not against it.
ℹ️

Designed for composability. Symfonix Business Suite is not an monolithic ERP you must adopt wholesale. Enable the modules your organization needs today and add others as requirements evolve — the core engine handles discovery, routing, and permission registration automatically.

System Architecture

Symfonix Business Suite follows a layered modular architecture where business logic lives in self-contained modules, orchestrated by a shared core engine and backed by a single relational database.

Business Modules (dynamically loaded)
CRM HR / User Finance Tax Reporting CMS Project Product Support
↕
Core System Engine
Module Registry Auth & Permissions Event Bus Shared Services Admin Shell (Inertia)
↕
Data Layer
MySQL / MariaDB Redis (cache / queues) File Storage

Each module is a first-class Laravel package under Modules/ with its own routes, controllers, models, migrations, views, and service providers. The core engine discovers enabled modules at boot time, registers their service providers, merges route files, and runs migrations in dependency order.

The Core Engine

The Core and Base modules form the system engine. Core provides the installation command (php artisan app:install), shared helpers, and bootstrap logic. Base handles global settings, countries, branches, SEO, backups, the file manager, /humans.txt, and the APIs & Integrations screen (SMTP and WhatsApp Cloud API). System Configurations also cover finance FX credentials and ZKTeco fingerprint device settings.

Key responsibilities of the core engine include:

  1. Module lifecycle — register, enable, disable, and migrate modules through standardized artisan commands.
  2. Permission synthesis — aggregate permission definitions from all active modules into a unified Spatie Permission registry.
  3. Admin shell — provide the Metronic-themed admin layout, navigation scaffolding, and Inertia page rendering pipeline.
  4. Cross-module events — Laravel's event system enables loose coupling (e.g., Finance listens for invoice-sent events from CRM subscriptions).

Data Consistency

Because all modules share a single database, referential integrity is enforced at the schema level — not approximated through nightly sync jobs. Foreign keys connect customers to deals, employees to salary records, products to stock movements, and projects to companies.

Spatie Laravel Data DTOs standardize data transfer between layers, ensuring type-safe payloads across module boundaries. Translatable models (via spatie/laravel-translatable) keep CMS content and product catalogs consistent across locales without duplicate records.

Concern Approach Benefit
Schema ownership Per-module migrations Modules evolve independently without central bottleneck
Shared entities Core/Base models (User, Country, Branch) Single source of truth for organizational data
Transactions Laravel DB transactions Atomic cross-table operations (e.g., stock deduction + invoice)
Audit trail Database logging + Telescope (dev) Traceability for compliance and debugging

Performance

Symfonix Business Suite is engineered for responsive admin experiences under real enterprise load:

  • Inertia.js delivers SPA-like navigation without the complexity of a separate frontend API layer.
  • Eager loading, query indexes, and repository patterns in high-traffic modules (CRM, Finance, Reporting) prevent N+1 query problems on lists, campaigns, and dashboards.
  • Redis (optional) accelerates session storage, cache, and queue processing for background jobs like invoice PDF generation and notification dispatch.
  • Laravel Pulse provides production performance monitoring when enabled.
  • Asset pipeline via Vite ensures optimized, cache-busted frontend bundles.

CRM & Pipelines

The CRM module is the revenue engine of Symfonix Business Suite. It manages the full lifecycle from first contact to closed deal, with visual pipeline stages, activity tracking, and subscription management for recurring revenue models.

Key Interfaces

  • Lead Management — capture, qualify, and convert inbound leads with custom fields, tags, and source attribution.
  • Deal Pipeline — Kanban-style pipeline with configurable stages (default: Lead → Qualified → Proposal → Negotiation → Closed Won/Lost). Drag-and-drop stage transitions with activity logging. Assignees see their own deals unless they have sales.deals.view_all.
  • Quotes / Proposals — line-item quotes with tax and discount, PDF download, create-from-deal, and a public customer link to accept or reject.
  • Company Records — B2B account management with linked contacts, deals, projects, quotes, and subscription history.
  • Activities & Tasks — schedule calls, meetings, and follow-ups tied to leads, deals, or companies.
  • Subscriptions — manage recurring service contracts with renewal tracking and Finance integration for invoicing.
  • Email marketing — queued campaigns to subscribers, contacts, inquiries, or custom addresses, with automatic email deduplication.
  • WhatsApp marketing — Meta Cloud API template campaigns to leads, contacts, deals, inquiries, or custom numbers. Messages are queued; delivery is logged per recipient.
  • Sales Forecasts — probability-weighted pipeline projections by stage, sales rep, and expected close date (best case / worst case).
  • CRM Dashboard — filterable KPIs, funnel, leaderboard, and activity feed. Users can show, hide, and reorder widgets.
  • Sales Targets — set and monitor team and individual sales quotas against pipeline performance.

Pipeline Workflow

Deals progress through pipeline stages defined in CRM/database/seeders. Stage transitions trigger events that other modules can listen to — for example, moving a deal to "Closed Won" can automatically create a Project record and generate a Finance transaction.

💡

CRM access is granular. Typical keys include crm.leads.*, sales.deals.view_all, sales.quotes.*, marketing.whatsapp.send, and sales.forecasts.view. Legacy names such as CRM Management are remapped on install.

People Access Control

Human Resources

The User module serves as Symfonix Business Suite's HR and identity backbone. It bridges employee records with system authentication, role assignment, and payroll integration through the Finance module.

Key Interfaces

  • Employee Profiles — comprehensive employee records linked to user accounts, including contact details, department assignment, and employment status.
  • Role-Based Access Control — powered by Spatie Laravel Permission with a group.tab.action catalog. Install seeds Admin plus scenario roles: HR Manager, Sales Manager, Finance Manager, Project Manager, and Operations Manager.
  • Permission Matrix — per-resource actions (view, create, edit, delete, plus send, export, approve, view_all, manage, reply, restore) assigned in User Management → Roles.
  • Fingerprint attendance — optional ZKTeco TCP/IP integration. Employee IDs map to device user IDs for enrollment and punch sync. Configure under System Configurations → Fingerprint.
  • Leave & hiring — leave requests, job positions, and job applications.
  • Portal Dashboard — employee-facing portal plus a customer portal for quotes and related records.
  • Team Module Integration — public-facing team member profiles for the company website, also listed in /humans.txt.

HR ↔ Finance Bridge

Employee records connect directly to Finance salary and commission tracking. When payroll runs, transactions are attributed to the correct employee with full audit history — no CSV imports between HR and accounting systems.

Accounting Revenue & Expenses

Finance

The Finance module provides end-to-end, multi-currency financial operations — from daily transaction logging to salary disbursement, commission calculation, invoicing, and expense categorization. It listens to events from CRM and Product modules to maintain accurate books without manual data entry.

Key Interfaces

  • Transactions — real-time ledger of income and expenses with categorization, filtering, and today's-transactions dashboard widget (Livewire).
  • Journal Entries — double-entry bookkeeping support for organizations requiring formal accounting practices.
  • Invoices — create from deals, PDF download, sent/paid/void lifecycle, tax lines, and customer notifications.
  • Accounts Receivable — outstanding and overdue invoice tracking for the finance dashboard and reports.
  • Salaries — recurring payroll management tied to employee records in the User module.
  • Commissions — sales commission tracking linked to CRM deal closures and sales targets.
  • Expenses — operational expense logging with customizable expense categories and input-tax capture.
  • Product Sales — revenue recording from Product catalog sales, connected to the broader commercial workflow for accurate reporting.
  • Invoice Notifications — automated customer notifications when invoices are sent, via Laravel event listeners.
  • Currency Context — separate accounting-base, transaction, and per-session display currencies with posting-time exchange-rate snapshots.

Event-Driven Integration

Finance uses Laravel's event/listener pattern for cross-module workflows. For example, NotifyCustomerOfInvoiceSent listens for invoice events and dispatches notifications — keeping Finance decoupled from CRM implementation details while maintaining data flow.

Multi-currency Setup

Symfonix separates three currency concepts: the default currency is the accounting base, each business record retains its transaction currency, and the admin-header selector controls only the user's display currency. Journal entries snapshot both the posting-time source-to-base rate and converted base amount; changing display currency never changes the stored posting.

SettingPurposeDefault
FINANCE_DEFAULT_CURRENCYAccounting base currencyUSD
FINANCE_SUPPORTED_CURRENCIESComma-separated currencies available to usersUSD,EUR,GBP,TRY
FIXER_API_KEYFixer or API Layer credentialEmpty
FIXER_BASE_URLExchange-rate API endpointhttps://data.fixer.io/api

Users with Settings Management can override the default currency and Fixer key under System Configurations → Finance; stored settings take precedence over environment values. The supported-currency list remains environment/config driven. Free Fixer plans return EUR-based rates, so Symfonix derives non-EUR defaults through EUR cross-rates.

Terminal 
# Queue a rate update (requires a running queue worker)
php artisan finance:fetch-exchange-rates

# Fetch immediately, optionally overriding the base
php artisan finance:fetch-exchange-rates --sync
php artisan finance:fetch-exchange-rates --base=EUR --sync
⚠️

Do not use fallback rates for production accounting. Installation seeds approximate baseline rates, and a missing Fixer key or unavailable stored rate can result in a 1.0 fallback. Configure and monitor synchronization before posting live transactions. Changing the default currency after postings exist requires a controlled migration because historical base amounts retain the original accounting base.

Compliance Ledger & Filing

Tax

The Tax module stores inclusive or exclusive rates (optionally scoped by region), applies them on invoice and product-sale lines, and posts collected output tax and paid input tax to a dedicated ledger. Filing reports summarize net tax payable for a date range and can be exported.

Key Interfaces

  • Tax Rates — percentage, inclusive/exclusive type, optional ISO region code, default rate for invoices and subscriptions.
  • Tax Ledger — chronological output and input entries linked to invoices, lines, and expenses.
  • Filing Report — period summary of tax collected versus tax paid.
Analytics CSV / PDF Export

Reporting

The Reporting hub provides cross-department analytics with shared period filters and CSV/PDF export. Each department has its own permission (reporting.finance.view, reporting.sales.export, and so on).

Departments

  • Finance — revenue, expenses, profit, AR aging, tax summary.
  • Sales — pipeline funnel, won/lost trend, rep performance.
  • Marketing — email and WhatsApp campaign volume, delivery rate, lead sources.
  • Operations — tickets, projects, fingerprint attendance.
  • Employee — utilization, assigned projects, salary trend, per-employee profile.
Content Multilingual

Content Management (CMS)

The CMS module powers the public-facing website alongside the admin panel. It provides a full content authoring environment with multilingual support, SEO integration, and rich text editing via TinyMCE.

Key Interfaces

  • Pages — create and manage static pages (About, Services, Contact) with slug-based routing and translatable content fields.
  • Blog — publish articles with categories, read-time estimation, featured images, and SEO metadata.
  • FAQs — structured frequently-asked-questions management for support and marketing pages.
  • Our Clients — logo/showcase entries for the public site.
  • SEO Settings — global and per-page SEO configuration managed through the Base module's SEO interface, including meta titles, descriptions, and Open Graph tags.
  • Services Showcase — the Services module extends CMS capabilities with service categories and offering pages for agencies and consultancies.

Localization

Content is translatable across English, Arabic, Turkish, and German via mcamara/laravel-localization and Spatie Translatable. RTL layout support is built into the public site theme for Arabic locales.

Getting Started

This guide walks through deploying Symfonix Business Suite from a fresh clone to a running admin panel with all core modules installed. The platform uses Laravel 13 with modular architecture — each business module is a self-contained package activated through the module system.

Requirements

Ensure your server or local development environment meets these minimum specifications:

Dependency Version Notes
PHP 8.3+ Extensions: BCMath, Ctype, JSON, Mbstring, OpenSSL, PDO, Tokenizer, XML
Composer 2.x PHP dependency management
Node.js 18+ With npm for frontend asset compilation
MySQL / MariaDB 8.0+ / 10.6+ Primary data store — single database for all modules
Redis 6+ Optional — recommended for production cache and queues

Installation

Follow these steps to deploy a fresh Symfonix Business Suite instance:

  1. Clone and configure environment

    Copy the environment file and set your database credentials:

    Terminal 
    cp .env.example .env

    Edit .env with your database connection:

    .env 
    DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=symfonix
DB_USERNAME=root
DB_PASSWORD=

FINANCE_DEFAULT_CURRENCY=USD
FINANCE_SUPPORTED_CURRENCIES=USD,EUR,GBP,TRY
FIXER_API_KEY=
FIXER_BASE_URL=https://data.fixer.io/api

DOCS_ENABLED=true

  2. Install dependencies

    Install PHP and Node.js dependencies, then compile frontend assets:

    Terminal 
    composer install
npm install && npm run build

  3. Run the install command

    The app:install artisan command handles the full bootstrap — migrations, seed data, the granular permission catalog, scenario roles, CRM pipeline stages, baseline currency settings and rates, and admin user creation:

    Terminal 
    php artisan app:install

    Custom admin credentials:

    Terminal 
    php artisan app:install \
  --email=you@company.com \
  --password=secret \
  --name="Your Name" \
  --mobile=1234567890

  4. Start the application

    Terminal 
    php artisan serve

    Visit /admin and sign in with the credentials displayed after installation. Documentation is available at /docs when DOCS_ENABLED=true.

💡

The install command generates APP_KEY, runs all module migrations, seeds countries and baseline currency rates, synchronizes permissions, seeds HR/Sales/Finance/Project/Operations role scenarios, seeds default CRM pipeline stages, and assigns the Admin role with full permissions.

Enabling & Disabling Modules

Module activation is controlled via module.json and the module status file:

Terminal 
# List all modules and their status
php artisan module:list

# Enable a module
php artisan module:enable Stock

# Disable a module
php artisan module:disable Testimonial

# Run migrations for a specific module
php artisan module:migrate CRM

Creating a New Module

To scaffold a new business module (e.g., a custom reporting module):

Terminal 
php artisan module:make Reporting

# Generate module components
php artisan module:make-controller ReportController Reporting
php artisan module:make-model Report Reporting -m
php artisan module:make-migration create_reports_table Reporting

Register permissions in your module's service provider and add them to the install command's permission seeder for automatic provisioning on fresh installs.

Production Deployment

For production environments, apply these optimizations after installation:

  1. Configure environment

    .env 
    APP_ENV=production
APP_DEBUG=false
CACHE_DRIVER=redis
QUEUE_CONNECTION=redis
SESSION_DRIVER=redis

  2. Install production dependencies

    Terminal 
    composer install --no-dev --optimize-autoloader
npm ci && npm run build

  3. Run migrations and cache

    Terminal 
    php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

  4. Configure background services

    Set up a queue worker and scheduler via cron. The scheduler performs a synchronous exchange-rate refresh every hour. Queued WhatsApp campaigns, marketing emails, and manual rate fetches require the worker.

    crontab 
    * * * * * cd /path-to-symfonix && php artisan schedule:run >> /dev/null 2>&1
⚠️

Production checklist: Ensure APP_DEBUG=false, restrict /admin access if needed, enable two-factor authentication, never commit .env, configure a valid Fixer key, and monitor the last successful rate fetch under System Configurations → Finance. Stored rates have no automatic staleness rejection. Set WhatsApp credentials under APIs & Integrations before sending campaigns. Set DOCS_ENABLED=false if you do not want to expose /docs.
